# Telegram-бот-модератор — дизайн

## Назначение

Бот для групповых чатов Telegram, который:
1. Периодически отправляет настраиваемое сообщение в чат (интервал настраивается админом).
2. Модерирует сообщения по списку триггер-слов, применяя эскалацию наказаний: предупреждение → мьют на 5 минут → кик.

## Стек

- Python 3.11+
- aiogram 3.x (long polling, `python bot.py`)
- SQLite через `aiosqlite`
- APScheduler (`AsyncIOScheduler`) для периодической рассылки
- Токен бота и прочие секреты — в `.env` (не в git), загрузка через `python-dotenv`

## Модель данных (SQLite)

- `trigger_words(chat_id INTEGER, word TEXT)` — доп. триггер-слова, добавленные админами команду для конкретного чата. Итоговый список слов для чата = объединение содержимого `moderation/trigger_words.txt` и строк из этой таблицы для данного `chat_id`.
- `warnings(chat_id INTEGER, user_id INTEGER, count INTEGER, last_violation_at TIMESTAMP, PRIMARY KEY(chat_id, user_id))` — счётчик нарушений пользователя в чате.
- `chat_settings(chat_id INTEGER PRIMARY KEY, broadcast_interval_min INTEGER DEFAULT 0, reset_days INTEGER DEFAULT 30)` — настройки чата. `broadcast_interval_min = 0` означает рассылка выключена. `reset_days = 0` означает счётчик нарушений никогда не сбрасывается по времени.
- `broadcast_messages(id INTEGER PRIMARY KEY AUTOINCREMENT, chat_id INTEGER, text TEXT)` — пул сообщений периодической рассылки для чата.

## Логика модерации

На каждое текстовое сообщение в группе, где бот состоит:

1. Пропустить, если автор — администратор чата или сам бот.
2. Если у пользователя есть `last_violation_at` старше `reset_days` дней (и `reset_days != 0`) — обнулить `count` до проверки.
3. Проверить текст сообщения на вхождение любого триггер-слова из объединённого списка (регистронезависимое сравнение, поиск подстроки).
4. При совпадении — увеличить `count` на 1, обновить `last_violation_at`, и в зависимости от нового значения `count`:
   - **1** → ответить в чат текстом-предупреждением, упомянув пользователя.
   - **2** → вызвать `restrictChatMember` (запрет отправки сообщений) на 5 минут, ответить в чат о мьюте.
   - **3** → вызвать `banChatMember`, сразу `unbanChatMember` (кик с возможностью вернуться по инвайт-ссылке), ответить в чат о кике, сбросить `count` на 0.
5. Сообщение с триггер-словом **не удаляется** — остаётся в чате.
6. Если Telegram API возвращает ошибку прав (бот не администратор либо не хватает прав на restrict/ban) — поймать исключение и один раз отправить в чат сообщение о том, что боту нужны права администратора для мьюта/кика (не спамить этим сообщением на каждое нарушение — использовать троттлинг, например не чаще раза в 10 минут на чат).

## Админ-команды

Доступны только пользователям с правами администратора/владельца чата (проверка через `getChatMember`).

| Команда | Действие |
|---|---|
| `/addword <слово>` | Добавить триггер-слово для этого чата |
| `/delword <слово>` | Удалить триггер-слово для этого чата |
| `/listwords` | Показать все триггер-слова (файл + добавленные) для этого чата |
| `/warns` (ответом на сообщение) | Показать счётчик нарушений пользователя |
| `/resetwarns` (ответом на сообщение) | Обнулить счётчик нарушений пользователя вручную |
| `/setresetdays <N>` | Установить период автосброса счётчика в днях (0 = не сбрасывать) |
| `/setinterval <минуты>` | Установить интервал периодической рассылки (0 = выключить) |
| `/addmsg <текст>` | Добавить сообщение в пул периодической рассылки |
| `/delmsg <номер>` | Удалить сообщение из пула по номеру (из `/listmsgs`) |
| `/listmsgs` | Показать пул сообщений рассылки с номерами |

## Периодическая рассылка

- При старте бота для каждого чата с `broadcast_interval_min > 0` регистрируется periodic job в `AsyncIOScheduler`.
- При изменении интервала через `/setinterval` job для этого чата пересоздаётся на лету (старый снимается, новый регистрируется, либо job снимается совсем при значении 0).
- На каждый тик бот выбирает случайное сообщение из пула чата (`broadcast_messages`) и отправляет его. Если пул пуст — тик пропускается без ошибки.

## Обработка ошибок

- Ошибки прав бота (не администратор, недостаточно прав) — ловятся, логируются, в чат отправляется троттлированное уведомление (см. п.6 логики модерации).
- Ошибки Telegram API при отправке периодических сообщений (например, бот кикнут из чата) — логируются, job для этого чата снимается автоматически.

## Тестирование

- Чистая логика (проверка триггер-слов, вычисление следующего наказания по счётчику, логика сброса по `reset_days`) выносится в отдельные функции без побочных эффектов и покрывается модульными тестами `pytest`.
- Реальные вызовы Telegram API (restrict/ban/unban, отправка сообщений) автотестами не покрываются — требуется ручная проверка в тестовой группе, где бот назначен администратором.
